# Yidie delivery board

This is the single working checklist for the first public, installable release. A box is checked only when its acceptance evidence is recorded. Simulator behavior and physical-device behavior are reported separately.

## Completed

- [x] iOS-first Expo/React Native app with local PhotoKit import, confirmed dates, persistent processing queue, SQLite records, and Apple Vision sticker generation.
- [x] Calendar-first interaction: sticker stacks, count badges, month-arrow navigation, month/day swipe handlers, animated sheets, centered Add action, English UI, and local identity. Touch-driven paging remains unaccepted until it works on a Simulator touch surface.
- [x] Local sticker outline editing: preserve the transparent cutout, preview and save color/width variants without rerunning Vision.
- [x] Distinguish not-yet-requested, authorized, limited, denied, and restricted Photos access; load an already-authorized library automatically and direct denied users to Settings.
- [x] Fence Settings export/restore/share actions synchronously against rapid duplicate taps; keep the sheet open while an operation or its queue cleanup is active.
- [x] Automated domain/SQLite, TypeScript, lint, formatting, native file-catalog, and documentation-contract checks.
- [x] Add a Simulator-only Expo launch command that validates an exact available iOS Simulator UDID and stops before Expo when CoreSimulator is unavailable; test selection fail-closed behavior without launching a device.

## P0 — keep user data safe

- [x] Implement a user-controlled `.yidie` package with a consistent SQLite snapshot and app-owned image assets; the Files picker lets users choose its destination.
- [x] Validate package layout, format/schema versions, checksums, file paths, counts, SQLite integrity, and size limits before restore.
- [x] Stage restores separately and use a startup-recoverable directory swap; rollback retains the current library if activation fails before commit.
- [x] Make backup/restore discoverable in Settings and explain that backup packages are unencrypted and uninstalling without a backup can remove local records.
- [x] Add deterministic native tests for package corruption, malformed foreign-key schemas/data, path traversal, future versions, storage limits, cancellation, interrupted swaps, and a live WAL database; verify the current Simulator database can be packaged and staged for restore. On the dedicated iOS 26.1 Simulator, save an empty `.yidie` package through Files, select it in Restore, confirm the 0-record replacement, and relaunch successfully to the calendar.
- [x] Give each repository one owned SQLite connection for reads and `BEGIN IMMEDIATE` write transactions. Serialize every repository operation and shutdown on one FIFO lane; close fences new work and drains the lane. Integration tests use the same transaction adapter and verify read/write/close ordering and rollback.
- [x] If a backup/restore pause request fails, restart only the processing work that was active before the request; preserve manually paused jobs and surface the failure. A regression test injects a failed pause and verifies the prior queue finishes its pending work.
- [x] Rebuild and smoke-test the earlier crash-report fix on the dedicated iOS 26.1 Simulator: while the calendar app was running, restore a valid empty backup from Settings, allow the database replacement/reopen, and confirm the app returns to the October calendar. The updated deterministic regression holds a read, proves a later write cannot enter native SQLite concurrently, then verifies `close()` drains the queue and rejects later work. The earlier Simulator flow did not force a deliberately blocked query at the exact close boundary, so treat it as lifecycle smoke coverage, not a concurrency stress test.
- [ ] Rebuild the single-connection SQLite change and stress a deliberately held read against a queued write and close/WAL checkpoint on a supported Simulator; verify the app stays open and library data remains available after close/reopen. A Simulator crash report on 2026-10-15 showed `run(statement:)` and `closeDatabase()` active on Expo SQLite's concurrent native queue at the same time. Removing per-write connections and routing close through the same owner lane addresses that interleaving in app code; the native rerun remains required.

## Definition of done

The first public release is done when P0 and P1 code items pass automated checks, all core screens pass a repeatable simulator walkthrough, one opt-in physical-device photo test passes or produces a clearly bounded fallback, all user data flows have rollback behavior, docs agree with the shipped app, CI is green, and a versioned build can be reproduced from the repository. Until then, call it a development build and keep this board current.
