# 落地前全量审查

审查日期：2026-10-13。结论：可以创建公开仓库并开始阶段 1–2；当前不是经过真机验收的正式 App，不能承诺绝对安全或直接发布。审查覆盖研究、PRD、UI、数据契约、原生边界、实施顺序、公开内容和验证方式。

## 高风险问题

| 问题 | 影响 | 决定与状态 |
| --- | --- | --- |
| 初始化命令使用 latest，未绑定当前 Xcode | 新工程可能无法本地编译 | 采用用户确认的 Expo SDK 57、RN 0.86、React 19.2，锁定 lockfile。本机需先升级 macOS 至 26.2+、Xcode 至 26.4+；升级前不宣称原生编译通过 |
| 通用照片选择器可能自动下载 iCloud 原图 | 与严格本地运行的承诺冲突 | 采用 PhotoKit 权限与资产列表，缩略图/原图所有请求禁止网络。JS 层不调用会自动下载原图的通用 picker |
| SQL 只验证日期字符串外形 | 可能写入不存在的日期，或跨午夜归错日 | 必须实现统一 DatePolicy：真实公历验证、EXIF 字面日期优先、显式用户日期优先、时区稳定；用闰日、跨午夜和缺失元数据测试验证 |
| 原生接口由 JS 指定任意输出目录 | 文件生命周期、备份排除、清理范围难以约束 | 原生模块统一管理 Application Support/Yidie 根目录和临时文件；只接受本库相对路径或原生返回的资源标识，不执行任意目录删除 |
| 未完成恢复却宣称备份可靠 | 可能导致不可恢复的数据丢失 | 恢复是完整首版的发布门槛。验证摘要、空间、路径、引用关系；隔离写入再切换；失败保留旧库；恢复的 running 任务统一暂停或重新排队 |

当前接口、队列和数据库属于设计基线，后续只有实际测试通过才能将上述实施要求标记为已完成。

## UI 与流程问题

贴纸替代日期、跨日期留白、同日最大三层和底部横向浏览已形成一致规则。已检查普通、密集与六周布局。正式实现还必须补齐以下行为：

- 原型部分操作只是提示，并不保存照片、日期或备份；禁止将其直接包装成 WebView App。正式操作必须返回真实结果。
- 日期、月份、年份与当前项必须使用稳定记录 id，不能沿用原型中固定的六月示例和数组索引。跨年切月、滑动后删除/设封面属于必测项。
- PNG 的透明边距不能用作视觉尺寸；布局要使用实际主体边界，旋转后整组再缩放，屏幕与导出共享规则。
- 原型的半身裁切只为示意构图；正式照片默认保留完整主体，不自动裁掉衣服或裤子。
- 普通文字主按钮需满足对比度要求，正式 token 将主操作文字按钮使用较深蓝色；装饰蓝可以保留原参考风格。
- 原生弹层应管理 VoiceOver 焦点和滑动手势。备份替换与清空数据必须二次确认，不能依赖隐藏按钮作为保护。

## 架构与产品方向

架构保持 RN 页面 → 用例 → 日期/布局领域规则 → 本地存储和原生模块。初期不需要状态管理框架、网络层、用户系统或通用插件体系。Swift 负责 PhotoKit、Vision 和图片文件；领域规则不放在页面组件内。

首版价值仍是“同一天多张穿搭自然叠放、轻松展开和分享”。批量导入、本地抠图、月历海报并非市场独有能力；不能把开源当作用户量保证。研究文档已说明安装门槛与停止条件。

公开模块的主要风险是日期、文件和布局规则同时影响导入、月历与导出。正式工程应使用单一实现；`specs/` 只作为版本化设计资料，不能维护另一套运行时模型。

仓库只包含项目文档、设计、生成的示例素材和代码。未发现提交内容包含令牌、证书、私钥、个人穿搭照片或用户提供的小红书参考截图。生成素材有来源说明；代码 MIT 许可不自动涵盖未来第三方照片。名称是工作名，未宣称商标或名称排他性。

GitHub 文档中的 HTML 链接展示源码，不等于托管预览；README 应提供截图和本地预览说明。不会自动发布网站、上架或配置云端业务服务。GitHub Actions 只进行代码检查，不接收 App 用户数据。

| 范围 | 必须验证 |
