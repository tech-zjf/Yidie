## 记录格式

每次测试填写：构建号、设备/系统、样本编号、操作、预期、实际、耗时/内存（需要时）、通过或失败、关联修复。样本照片只保存在自有测试设备；公开 issue 仅包含用户同意分享的素材。

首版不存在统计 SDK，因此产品反馈通过主动访谈、构建反馈和自愿 issue 收集。测试者不能成功安装，应单独记为分发问题，不能直接视为不喜欢产品。

## iOS Simulator 验收顺序

使用固定合成场景重复验收。先从 `apps/mobile` 运行 `npm run preview:ios`，选择 populated month；手势和布局都通过后，再运行生产入口的 Release 构建验证系统面板。UI 预览不接触 Photos、真实 SQLite 库或 Vision，不能代替真照片和系统 API 验收。

1. **月历与同日堆叠：**确认有照片的日期不再显示日期数字；单张可点开；多张露出错开的贴纸并显示该日总数。横向拖动月历中央区域切换相邻月份，确认月份标题、日期、贴纸同时更新；再点箭头验证边界月份与跨年。轻点日期格仍只打开该日，不误触月份切换。
2. **当日浏览与弹层：**打开含多张样例的日期，横向逐张滑动；照片、`当前张/总张`和编辑目标一起变化。点编辑后返回应保留当前张；从手柄下拉、点遮罩和点关闭分别收起。检查打开/关闭都从底部平滑过渡，减少动态效果打开时应立即完成且不残留遮罩。
3. **贴纸效果编辑：**分别预览原图、描边、漫画、立体感和闪亮；描边效果可选白/深色/蓝色和多档粗细。预览但不保存后退出，旧样式仍在；保存后日历缩略图、当日详情与分享素材使用同一新版本。样式编辑不能更改原图和透明抠图；效果只承诺视觉近似，不承诺与 Apple Photos 1:1。
4. **原生系统面板：**在 Release 构建中分别导出、取消和完成 `.yidie` 备份；恢复一份有效合成样例包；再选择损坏包，确认拒绝且当前库保持不变。测试分享贴纸与月历图的系统面板，并取消一次；日期选择器选新日期、取消一次，再保存一次并确认记录移动到正确月份。系统面板的取消不应改变记录。
5. **尺寸与辅助功能：**在最小支持 iPhone 尺寸、动态字体较大和 6 周月份下检查首页不裁切按钮且无不必要滚动条；VoiceOver 顺序应先读标题、月份/操作、日历日期与数量、底部操作；效果与描边控件需读出选择状态；减少动态效果应尊重系统设置。

任何一项失败，记录具体设备、iOS、构建和步骤，并修复后从受影响流程的第一步重跑。只有生产入口构建的系统面板可作为原生流程证据；预览场景只作为固定样例和布局证据。模拟器服务断开时不重置设备或强行重启服务，先完成静态检查并等待安全恢复条件。
