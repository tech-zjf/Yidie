# 阶段 4：批量导入与队列复审

2026-10-13。范围：本地相册多选、日期分组确认、重复检测、持久处理队列、暂停/恢复、界面状态刷新和 v3 迁移。按 requirement-code-review 检查功能、数据生命周期、共享接口、UI 与回归。结论仅针对开发基线，不是发布验收。

## 高风险问题

复审发现并已修复的路径：

- **预览查重不等于提交查重。** `queueRepository.queueBatch` 在同一事务内按内容摘要或相册资产 ID 再查一次；任一未确认重复或无效日期使整批回滚。重复默认跳过，只有用户明确包含的重复项才允许新增。新出现的重复会返回确认页供处理。
- **关闭确认页不能删掉已归档原图。** 提交前将副本所有权移交给提交操作；提交成功后记录持有原图，失败后交回草稿。`discardDrafts` 删除前检查数据库归属，无法确认时保留。普通关闭和移除会清理未归档副本，进程被杀产生的孤儿文件对账仍未实现。
- **暂停原因不能混用。** v3 增加 user/background/interrupted/storage。回前台只恢复 background；主动暂停和重启恢复等待用户操作。恢复同步递增记录与任务的 revision，旧结果不能覆盖新任务。
- **状态写入失败不能当成单张抠图失败继续。** 如果处理失败后记录仍为 running，调度器停止并显示重启提示；本次会话不再启动队列。冷启动将未完成项归为 paused，再手动继续。测试使用 SQLite 触发器阻止结果写入，验证后续项没有开始、记录保留且重启后可恢复。
- **队列与手动操作不能同时处理图片。** 批处理、单条重试和文件删除共用串行执行器。确认先持久化所有任务，普通图片失败不阻塞后续，空间不足暂停剩余任务。

代码复审未发现剩余的同类阻断问题。测试使用本地 SQLite 与可控的图片能力替身，不能代替磁盘耗尽、系统挂起或断电的设备实测。

## 中低风险与验证缺口

- 当前工具链仍未满足 Expo SDK57 的完整原生构建要求；尚无本轮 iPhone 界面截图、真实 Vision 批量处理或 Release 离线结果。
- 单批 10 张是开发保护上限，尚未测得峰值内存或耗时；不得直接扩为 50 张并宣称流畅。
- 新选择页、分组编辑页和队列提示需检查 320pt、小屏、大字体、键盘、VoiceOver、长错误文案及相册有限权限变化。已加入行内换行约束，但不是视觉验收证据。
- 队列更新会刷新当前月和已载入记录；分页中的更新延后到查询返回，保留已加载页和位置。编辑页拒绝过期读取覆盖较新状态，同时保留未保存的日期输入。真实交互与滚动仍需原生测试。
- 未确认照片的崩溃残留文件、完整备份恢复、导出和主体选择仍未实现。开发版继续仅用于测试照片。
- 未修改依赖或 Swift 源码；两项既有上游依赖告警、尚未启用的 GitHub 检查模板维持实施记录中的边界。

## 架构与产品方向

| 模块 | 职责 |
| --- | --- |
| `features/import` | 相册分页、多选、分组确认、日期编辑、草稿生命周期和文案展示 |
| `domain/batchDraft`、`prepareBatch` | 日期分组、提交规则、顺序读取、重复与取消处理，通过注入接口测试 |
| `domain/processingQueue` | 前台调度、暂停意图与可订阅快照；持久任务仍由 SQLite 管理 |
| `domain/entryActions` | 组装提交、队列、重试和清理，共用一个串行执行器 |
| `data/queueRepository`、`insertPhoto` | 批量事务、重复复查、任务领取、状态迁移与共用写入 |
| `features/processing` | 月历与提交结果页共享的队列入口，用 useSyncExternalStore 读取快照 |

没有新增后端、账号、网络请求、全局状态库或依赖。领域层保持无 React/Expo 依赖，界面不执行 SQL。日期、字体、颜色和有图隐藏日期数字的规则沿用原方案；本轮没有修改贴纸几何布局。日期编辑在原弹层中切换内容，确认按钮不会在未保存日期的子页面中提交整批。

## 回归与检查结果

- `npm run check`：严格类型、ESLint、Prettier 和 37 项测试通过。
- `npm run export:ios`：iOS JS/Hermes 与两份本地字体打包通过，不是原生构建。
- `python3 scripts/check_packet.py`：文档路径、原型、SQL 约束及生成 SQL 同源检查通过。
- 新测试覆盖顺序读取、取消、普通/空间错误、查重失败清理、缺失日期、显式重复同意、批量回滚、暂停原因、前后台/重启、失败隔离、单并发、数据库异常停止、v1/v2 升级及多页记录刷新。

设备验收顺序：一张本地照片断网成功 → 10 张混合日期/重复/缺日期确认 → 普通失败与单条重试 → 暂停、切后台、回前台、杀进程恢复 → 日期/封面/删除 → 月历与列表状态刷新 → 小屏与无障碍 → 内存和耗时。每一步记录设备、系统和构建配置，再决定是否放大批量。

## 总体结论

可提交为阶段 4 开发基线。完整原生构建、真实照片效果、RN 视觉、离线与性能门槛仍未通过；环境升级后先完成这些验收，不把自动测试通过写成可发布。
