## Verified in this worktree

- The ExpoSQLite header-search issue was fixed by an idempotent config plugin scoped to ExpoSQLite, with template-contract tests. Earlier local CocoaPods attempts were blocked by DNS; the clean hosted build described below later verified the fix through Expo prebuild, CocoaPods installation, and Xcode 26.6 compilation.
- Current checks after the SQLite single-lane change, backup-manifest classification, month-swipe responder change, and Simulator-only launcher: TypeScript, ESLint, Prettier, all 70 domain/SQLite/preview/tool tests, native backup/file-inventory tests (including live-WAL packaging, the picker URL shape, malformed counts, malformed foreign-key schema/data, and oversized declarations), Swift core typecheck, repository/SQL contracts, and packet checks pass. The iOS JS export bundles 700 modules successfully. A malformed foreign-key package is rejected and leaves the current library intact; the initially suspected query-error misclassification was not reproduced because SQLite rejects this schema during statement preparation. Validation now also checks that row scans complete with `SQLITE_DONE`. Repository regressions prove public operations are serialized, close drains the lane, and rejected work does not poison later calls; a post-fix unsigned Release build plus empty-backup Simulator restore/relaunch smoke test was completed before this latest serialization change. A queue regression also confirms that a failed backup suspension resumes previously requested work without resuming manually paused jobs. The Simulator launcher tests prove that it forwards only a validated Simulator UDID, rejects physical UDIDs and device names, and stops without invoking Expo when inventory is unavailable; no device was launched in this verification. The latest single-lane change still needs native build and Simulator stress verification. Clean and scene-switching preview bundles both export; the normal Release JavaScript export was checked for and contains no preview scene or fixture code. The standalone Swift exporter typecheck checks API/type correctness, not the rendered image.
- The latest native backup-validation diff passed a complete unsigned iOS Simulator Release app build with Xcode 27.0 across the app and CocoaPods targets. The build did not launch Simulator or access a physical iPhone.
- The month swipe responder now explicitly refuses mid-gesture termination after it has classified a horizontal drag, while vertical movement remains delegated to the calendar scroll view. The pure gesture thresholds are unit-tested; this code change has not yet been verified on a touch surface.
- iOS JavaScript export and unsigned iOS Simulator Release and Debug builds passed in Xcode 27.0. The latest preview source ran on a dedicated iPhone 18 Pro / iOS 27 Simulator. Taps opened a populated month, a same-day ten-entry stack, the day sheet, and the style editor; a dark outline preview was saved and visible on return. The current unsigned Release build was separately installed and launched on the dedicated simulator; the one-screen empty calendar, month arrows, All Records sheet, and Add explainer were checked. The system photo picker was not opened.
