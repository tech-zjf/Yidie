# 分阶段实施方案

先解决真机上的照片、日期和本地抠图，再实现完整 UI。阶段 2 是继续投入的技术门槛；阶段 9 是继续维护的用户反馈门槛。下面的天数指单人有效开发日，合计约 15–25 天，受原生经验、设备和分发条件影响。

实际进度和未通过的关卡统一记录在 [实施记录](09-build-log.md)。代码组织遵循 [工程约定](10-engineering.md)。

## 阶段 0：产品与仓库基线

本次已整理 PRD、研究、技术方案、11 个 UI 入口、数据契约和检查脚本，项目目录命名为 Yidie。创建独立 Git 仓库，并按用户授权发布到 GitHub 的 tech-zjf/Yidie。首个基线提交应包含文档、设计和素材来源，不包含真实用户照片。

UI 已有交互设计，但需要由你决定视觉是否达到想做的程度。尤其体验 6 月 12 日的多张展开，并查看满月排版。此阶段不需要安装 Expo 或付费服务。

## 阶段 1：创建 App 基础工程（约 1 天）

前置：安装并确认 Node LTS、包管理器、Xcode、iOS SDK 和模拟器可用。创建时查阅 Expo 当前版本兼容要求，锁定最终版本与 lockfile；不要把文档中的 latest 当成长期构建依赖。

用户已确认采用新版 Expo SDK 57，并稍后升级 macOS 与 Xcode。最低工具链要求 macOS 26.2+、Xcode 26.4+。以下为初始基线步骤，实际实施状态见 README：

工程已初始化，继续开发使用已提交的版本与 lockfile：

```sh
cd apps/mobile
npm ci
npm run check
npm run ios
```

模板来源为 `expo-template-blank-typescript@57.0.30`；实际依赖见 package.json。原生模块名 `yidie-native`，仅实现 iOS。通过 app.json / 配置插件声明最低系统、照片权限和字体，保留 modules 为原生源代码；生成的 ios 目录不提交。不要重跑初始化命令或一次性安装尚未使用的依赖。

交付：`apps/mobile/App.tsx` 入口、`src` 分层、主题 token、lint/typecheck、基础 smoke test、构建说明；清除模板无关页面。第一屏放一个真实 RN 月历静态布局。

验收：开发构建在真机打开；自定义模块返回平台能力；仓库没有证书或私钥。是否提交生成的 `ios/` 目录在此时选择并记录，推荐使用可再生的 Expo 配置 + 本地模块，避免双重配置来源。

## 阶段 2：打通一张照片（约 2–3 天）

先做开发用验证页，依次显示选择照片、读取元数据、确认日期、抠图、白边、保存路径和结果。阶段完成后该页面从正式导航移除。

重点验证：HEIC/JPEG 方向、多人物、发丝、宽松外套和包；照片权限有限时 asset id 是否存在；iCloud 未下载原图能否可靠拒绝；Apple Vision 在目标真机上的能力和耗时。照片留在用户设备，不为调试上传。

交付：`modules/yidie-native` 原生能力与错误码、20 张照片的本地评估记录、无网络读取方案、实际性能范围。使用 `npx expo run:ios --device` 构建，真机开发签名由用户本地配置。

验收：一张照片在飞行模式下成功生成透明贴纸；断开 Metro 的 Release 版仍能冷启动并完成。若原生抠图效果或严格本地照片导入无法满足要求，先修正能力边界，不继续铺开页面。

## 阶段 3：本地数据与日期（约 2 天）

当前已在等待工具链升级期间实现日期/封面/删除/单条重试、迁移与 SQLite 集成测试；真机恢复和文件验证未通过；持久批量队列的代码现已在阶段 4 实现。具体边界见实施记录。

实现 schema migration、EntryRepository、FileStore、DatePolicy、持久化处理队列。根据 [SQL 契约](../specs/schema.sql) 和 [接口契约](../specs/contracts.ts) 落地，保留业务规则的纯函数。

交付：新增记录、改日期、设封面、删除、重启读取；文件路径都相对于自有数据根目录；数据库及图片排除系统备份。

验收：闰日和跨午夜照片归档正确；切换设备时区不移动日期；移动封面和删除后数据不悬空；任务中途退出能恢复；磁盘不足不会产生虚假的 ready 记录。

## 阶段 4：批量导入（约 2–3 天）

当前已实现选择、分组确认、重复检测、持久单并发队列和恢复的代码；37 项领域/SQLite 测试通过，见 [阶段 4 复审](12-stage4-review.md)。每批暂限 10 张。尚未完成原生交互、真实照片批处理和性能验收，不能标记该阶段设备门槛已通过。

实现选择、分组预览、日期来源、改组/改单张、重复提示、待归档、任务进度与重试。预览界面以原照片缩略图展示，确认后才生成贴纸；设计稿使用贴纸作为演示占位，不要求真实导入前先抠图。

交付：`features/import` 与单并发队列。先从 10 张验证，再测试 50 张；设置合理单批数量上限须由实测决定，并在选择页说明。

验收：部分失败仍完成其他图片；从某日进入时日期优先级正确；取消和后台暂停含义明确；照片只在 iCloud 时不会偷偷触发下载。

## 阶段 5：月历与同日弹层（约 2–3 天）

2026-10-14 已修复资源缓存、原图预览与中断导入文件回收，并准备 [固定 RN 预览场景](14-ui-preview.md)。尚未完成本阶段的原生 UI 还原验收；下一步先通过完整原生构建和单张真机门槛，再对照设计调整弹层高度、记录双列布局、贴纸白边/阴影与交互。

从设计 token 实现 MonthHeader、MonthGrid、DayCell、StickerStack、DaySheet、StickerPager。先保证贴纸替代日期的排版和空格日期可读，再加动效。组件接收布局描述，不在 render 中随机旋转。

交付：默认当前月、切月、空白页、1/2/3/10 张堆叠、横向分页、封面更新和继续添加。为各状态加入开发预览，但正式版不出现原型页面导航。

验收：日历 4/5/6 周、窄屏、31 天满记录、大字体下贴纸与空格日期不互相遮挡；手势不会误关闭弹层；再次进入选中正确照片。收集真实照片的高矮、半身、长裙布局效果。

## 阶段 6：记录编辑与导出（约 2–3 天）

实现日期编辑、样式保存、原照片查看、全部记录与待归档入口。实现单张透明图和整月白底导出，调用系统分享面板。确认支持主体选择时再开放相应入口，否则采用照片样式降级。

交付：纯布局函数在屏幕与导出之间共享；导出不带系统状态栏和 App 控件；署名可关闭；取消分享无数据副作用。

验收：预览与导出日期、封面、角度一一对应；图片可在相册正常打开；分享文件无 GPS 元数据；删除不影响系统相册原照片。

## 阶段 7：备份、恢复与异常（约 2–3 天）

实现 `.yidie` 备份、manifest、摘要和恢复摘要页；失败不替换原库，成功后原子切换。补齐空间不足、权限变化、损坏图片、版本过新、恢复中断和卸载提示。

交付：`features/settings`、`data/backup`、恢复阶段标记及启动修复。

验收：备份后在全新安装中恢复，条目、日期、封面、样式和图片一致；恶意路径/截断包被拒绝；恢复后重新排除系统备份。不能仅用“备份导出成功”替代恢复验证。

## 阶段 8：Release 与离线验收（约 1–2 天）

构建包含本地 JS bundle 的 Release，在真机断网、关闭 Metro、重启 App 后执行核心流程。使用系统工具检查网络请求，检查生产依赖没有遥测、更新检查或远程资产。模拟器通过不能替代真机结论。

可从工程目录尝试 `npx expo run:ios --device --configuration Release`；实际签名和归档方式以所选 Expo/Xcode 版本为准，记录可复现步骤。

交付：[验收清单](07-verification.md) 的实际结果、已知问题、支持系统与设备说明。只有完成这一步，README 才能从“设计基线”改为“可离线运行的 App”。

## 阶段 9：开源展示与小规模反馈（约 1–2 天准备）

准备 20–30 秒录屏：批量导入 → 自动分组 → 同日堆叠 → 横向展开 → 月历导出。README 首屏放动图、中文定位、英文简介、一条明确的本地构建路径。独立介绍 Native Vision 模块和日期边界，给开发者具体的学习理由。

公开仓库前检查 demo 素材权利、许可证、名称占用、签名配置和隐私内容，更新真正的仓库链接。用户已授权创建 GitHub 仓库并提交；公开内容按本次审查范围执行。后续可提供 TestFlight 测试，开发者计划和外部测试流程另行确认。

招募 5 位体验者，按研究文档的继续/停止条件评估，不把增加功能当作低关注度的默认解法。
