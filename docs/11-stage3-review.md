# 阶段 3 代码复审

2026-10-13。范围：日期修改/待归档、封面、删除、单条重试、数据库迁移、游标查询与对应 RN 入口。依据 requirement-code-review 的功能、数据生命周期、公共模块和 UI 检查项执行。这里区分代码结论与设备结论。

## 高风险问题

以下发现已经修复并加入回归测试：

- 重复提交导入时，INSERT 失败不代表原图没有持久归属。导入用例先查询归属；已有记录或无法确认归属时保留原图。
- 数据库提交删除与文件删除无法原子完成。删除事务同步写入 file_deletions；文件删除后才确认清理，失败或退出后在下次启动继续。
- 重试后不能接受旧任务返回结果。重试递增 revision，完成与失败均检查 revision；开始重试、记录和任务更新在同一事务中。
- 修改封面日期或删除封面不能留下悬空引用。仓库通过已有触发器清除旧封面、保留目标日期原有封面，并在事务内清除空日期。

当前代码审查未发现剩余的同类阻断问题。以上结论不替代真机磁盘不足、杀进程或文件保护测试。

## 中低风险与验证缺口

- Xcode 仍为 26.1.1，macOS 仍为 26.0。完整原生编译、Expo SQLite 在设备上的连接生命周期、真实文件删除和 Vision 效果未验收。
- 新编辑入口尚未在 iPhone 上检查小屏、大字体、键盘、横向列表和 VoiceOver。当前日期仍使用 YYYY-MM-DD 输入。
- Node 22 的 SQLite 集成测试运行同一套 SQL 仓库，但图片处理使用测试替身，不能据此声称真机离线链路通过。
- 已处理“记录删除后残留文件”；导入确认前退出留下的无数据库归属文件仍待孤儿文件对账阶段。
- 依赖审计中两项既有上游告警仍按实施记录保留，未在本轮修改依赖版本。

## 架构与产品方向

- 功能入口在 features/records，复用现有弹层，不新增后端、网络、全局状态库或嵌套 Modal。
- EntryRepository 是应用接口，SQL 实现按查询/普通变更/处理状态拆分；Expo 连接单独适配，真实 SQLite 测试使用相同仓库代码。
- DateField 在导入与编辑中复用；文案、颜色、字体继续统一管理。月历有记录时隐藏日期数字的规则未改变。
- 记录列表采用 (sort_key,id) 游标和索引，新增/删除不会改变后续页边界；月历仍只读当前月份。
- 单并发 worker 处理导入、重试和文件删除。它不是已经完成的持久批量导入调度器，产品边界在实施记录中保留。
