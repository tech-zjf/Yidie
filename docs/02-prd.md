# 衣叠产品需求

衣叠 v0.1 面向会保存穿搭照片的人，提供轻量、离线的日期记录与回看。用户不用先录入每件衣服，也不需要注册账号。首版成功的标准是：照片放对日期、贴纸好看、同日多张容易浏览、数据始终可带走。

## 范围

平台为 iOS；技术为 Expo / React Native，原生模块承担本地照片读取与抠图。最低系统以 iOS 17 为起点，同时满足选定 Expo SDK 的最低要求。前期不公开上架，不做安卓、订阅、社区、自动穿搭推荐、AI 试衣或云同步。

v0.1 包括月历、批量导入确认、贴纸生成与本地样式、同日浏览、改日期和封面、全部记录、图片导出、本地备份和恢复。编辑器提供 VisionKit 可识别主体的候选选择；多人重叠时系统可能仍将其识别为一个主体，不能手工涂抹修复，精细遮罩编辑列入 v0.2。该流程仍需 Simulator 与用户选择的真实照片验收。

贴纸抠图优先用 Apple 公开的 VisionKit 主体提取，并按透明像素边界裁紧，避免原图空白让贴纸缩小；VisionKit 不可用或失败时，回退到 Vision 人物实例分割，再回退到通用前景分割。用户可查看 VisionKit 识别到的主体并选择单个候选；重叠主体可能被系统识别为一组，且目前没有手工涂抹遮罩。Core Image 负责衣叠自己的离线效果。Apple 没有公开照片 App 的具体贴纸效果处理链路，因此 Outline、Comic、3D 和 Shimmer 是独立实现，不得宣称与照片 App 1:1 相同，也不调用私有接口。每个效果必须在用户选取的真实测试照片上检查边缘、透明背景、裁切和性能；不合格的效果不开放为可保存选项。实现依据：[Vision 人物实例分割](https://developer.apple.com/documentation/vision/vngeneratepersoninstancemaskrequest)、[VisionKit 主体提取](https://developer.apple.com/documentation/visionkit/imageanalysisinteraction/subject)、[Apple WWDC：在 App 中提取图像主体](https://developer.apple.com/videos/play/wwdc2023/10176/)、[Core Image 风格滤镜](https://developer.apple.com/documentation/coreimage/stylizing-filters)。

## 主要流程

### 从日历指定日期

打开默认展示当前真实月份。点击某天：有记录时打开当天底部弹层，没有记录时展示“为这一天选照片”。用户选择一张或多张后，全部放入指定日期；照片自身的拍摄时间不覆盖用户的明确选择。导入前说明目的日期，导入后可以修改。

### 从添加按钮批量导入

点击底部加号，打开照片选择器。返回 App 后先展示按建议日期分组的确认页，显示照片数量与日期来源。用户可以修改单张或一组日期，移除选中项，再确认导入。

当前开发版使用 App 内的 PhotoKit 本地相册页，每批最多 10 张；该上限需真机测量后再评估。读取中“停止读取”在当前文件读取返回后生效，已读照片保留供确认，其余照片可重新读取。重复项默认跳过，用户可逐项选择“仍然添加”；提交时在数据库事务内再次检查。

日期可靠时自动建议日期，不可靠时显示“待归档”。不使用文件最后修改时间推测拍摄日，不静默填今天。确认后先保存原照片和任务，再逐张生成贴纸，已完成项即时显示在月历。失败项可重试，不能阻塞整批。

### 一天有多张

一天的记录数量不因展示空间受限而截断。月历只绘制最多 3 张，角度与位移固定；有记录时不显示该格日期数字，多张时在叠图角落显示总张数，空格保留日期。点击后底部弹层显示日期、总张数，并横向分页浏览全部照片，左右露出下一张的边缘。当前项可以设为月历封面、编辑、分享或删除。更换封面不改变拍摄日期和导入顺序。

### 分享与保存

分享单张可导出透明贴纸；分享月份可导出白底高清 PNG。预览与导出使用同一套布局数据；日期和贴纸不会在导出时重新随机排列。默认不带署名，用户可在分享设置里主动开启小型 Yidie 品牌字标。导出的图片不写入原图 GPS 等元数据。

### 本地数据

导入文件复制到 App 自有持久目录，不能只保存相册引用。原照片仍由系统相册管理；删除 App 记录不会删除系统相册文件。完整备份包含原图、抠图、日期、样式和封面，恢复前验证并展示摘要，用户确认替换当前库。卸载会移除本地 App 数据，所以设置页明确提示先备份。

## 日期规则

| 情形 | 处理 |
| --- | --- |
| 用户从某一天导入，或手动改日期 | 用户选择优先，保存 dateSource=user |
| 照片含原始拍摄时间及偏移 | 使用拍摄地当时的年月日；保留来源信息 |
| EXIF 有日期但没有偏移 | 使用 EXIF 写入的日历日期，标记时区未知，不擅自转 UTC |
| 没有 EXIF，但相册提供 creationDate | 以导入时选定的时区推导建议日期，来源标为相册；由用户在预览确认 |
| 无可靠日期、解析失败、日期明显异常 | 待归档，不占据某天格子 |
| 用户后来旅行或切换时区 | 已确认的 recordDate 不变 |
| 同一天多张 | 全部保留，默认按拍摄时间、导入顺序、id 排序 |
| 同一照片再次选择 | 同库内以相册 id 和内容摘要辅助提示重复；允许明确选择“仍然添加” |

“保证日期”指尊重用户确认后的日期且不再漂移，不能保证来源照片的元数据一定真实。截图、编辑和转发可能丢失拍摄时间。

## 状态与失败处理

日期状态与抠图状态独立：一张照片可以已经生成贴纸但尚未确认日期；也可以日期确定但抠图失败。待归档记录存在本地库中，不显示在随意指定的日历格。

任务状态为 queued → running → ready / failed / paused。离开前台停止领取下一项，回前台仅自动继续因后台而暂停的任务；主动暂停、空间不足和冷启动恢复后的任务需手动继续。不承诺 iOS 后台持续计算，也不承诺当前原生任务一定能在挂起前完成。取消尚未确认的选择清理未归档副本；已入库任务使用“暂停处理”，保留原图和待处理项，删除需用户单独操作。数据库无法保存结果时停止队列并提示重启恢复，不能静默跳过状态异常。

磁盘不足时停止接收后续照片，保留已完成部分并显示数量；没有主体时允许照片样式；已删除记录的后台结果必须丢弃。所有破坏性数据操作都提供准确确认文案。

## 产品验证

采用主动招募体验者和可选反馈，不嵌入远程行为采集。记录一次使用需要几步、日期纠错次数、抠图失败类型和愿不愿继续使用；用户可主动提供截图和匿名反馈，不要求上传私人照片。
