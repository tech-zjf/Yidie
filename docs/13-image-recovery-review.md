# 图片与文件恢复复审

日期：2026-10-14。范围为阶段 4 后的图片资源、缓存、文件归属和 UI 预览准备；不表示整个 App 已完成验收。

## 高风险问题与处理

1. **抠图完成后可能继续显示照片。已修正。** 原先照片和贴纸使用相同 entry ID/revision 的缓存键，完成处理不一定改变 revision。现在四个记录界面共用 `RecordImage`：照片预览以不可变路径标识，贴纸以实际路径 + revision 标识，并设置 recyclingKey。测试覆盖完成前后、缩略图/详情图和重试。
2. **等待/失败记录直接读取大原图。已修正。** 导入返回前从自有原图生成最长边 512px、修正方向的 JPEG；数据库 v4 保存路径与尺寸。缺预览的旧记录显示占位并按需补建，失败保留记录，界面不回退加载原图或读取相册。
3. **确认前中断会遗留无主图片。已补恢复路径。** UI 开放前对账四个自有图片目录。只接收规范 UUID 命名的普通文件，事务内一次读取记录 ID 与路径引用，将确认无主的 ID 登记到持久删除任务。读失败保留文件；删除失败保留任务。未知文件、符号链接、数据库及系统相册不参与回收。

本轮范围内未发现尚未处理的高风险逻辑问题。文件系统和数据库不具备跨系统事务；强退、文件保护、空间不足的设备表现仍须真机验收，测试替身不能消除此验证缺口。

## 中低风险与验证缺口

- **原生 UI 还原尚未通过。** 当天仍使用 pageSheet，全部记录仍为单列；设计中的较低底部弹层、双列图墙、白边厚度和阴影尚需调整。字体已随包，但字形度量、间距与真机观感没有截图证据。
- 日期编辑仍为 YYYY-MM-DD 输入，有限照片权限的增选入口、大字体、键盘、VoiceOver、手势需要补齐或实测。
- 旧记录补建预览后，当前月格可能暂用占位比例；图片仍在单格内 contain，下次记录刷新采用已保存尺寸。不宣称所有照片都已达到最佳视觉比例。
- 启动对账按文件数和记录数增长，避免了逐文件全表查询；千条数据的冷启动耗时尚未测量。
- `PhotoPreview` 已通过 iOS SDK 类型检查，未实际执行 HEIC/镜像/方向样本。Expo 原生桥接尚未完整编译和链接。
- 新预览使用几何素材和只读替身，不能替代真实照片、Vision、处理进度或持久化验收。入口隔离经过打包检查，界面尚未运行。
- 未调整依赖，之前记录的上游依赖告警仍需发布前复核。

## 架构与历史影响

- 资源选择在纯领域函数，呈现在共享记录组件；页面不执行 SQL，也不直接导入原生实例。
- `imageMaintenance` 组织对账与补预览，`imageRepository` 负责事务和归属，Swift 分别负责文件清单和降采样。没有新增全局状态库或网络能力。
- 图片处理、预览补建和删除共用同一个串行执行器，避免删除之后出现迟到的新文件。
- v4 仅增加可空预览字段；不重算日期、改封面或 revision，不改写旧迁移。历史图片路径不靠猜测填入数据库。
- 预览是开发构建的独立入口，真实入口不导入它；只读端口拒绝写入，避免以 UI 隐藏按钮代替数据隔离。

## 结论

可提交为开发中的修复基线。完整原生构建和真机验收仍是下一关；不能称为可发布版本。先验证单张原生链路，再修齐 UI 与批量体验，之后继续导出、备份和开源展示。
